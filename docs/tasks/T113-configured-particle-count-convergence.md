## Objective

Resume the particle-count convergence experiment that T101 could not execute, using the exact 24-state configured-Search-domain support cohort recovered and accepted by T112.

T113 asks one bounded falsifiable question:

> with the T112 public states, current accepted native source, public-consistent hidden-future sampler, unguided Search-v2@400 continuation, configured Search decision domain, and sampler-seed rule fixed, how stable are the cross-particle strategy-fusion proxy values and searched decision classes as particle count increases through nested N=2,4,8,16,32, including independent sampler-seed replication and measured cost?

This is a convergence-and-cost diagnostic only. It does not create a deployable normal-information controller, exact public-information value, posterior value, or information-set-optimal policy.

For one admitted public information state `I`, one **searched Search-equivalence decision class** `c`, and public-consistent hidden-future particles `H_j`, T113 may compute the descriptive quantity:

```text
M_N(I, c) = (1 / N) * sum_j q_full(H_j, c)
```

where `q_full(H_j, c)` is the accepted per-particle full-state Search-v2 strategy-fusion proxy associated with that searched native source edge/class.

The aggregate must be called `strategy_fusion_mean_proxy` or equivalent. It must not be called `Q_public`, posterior expectation, regret-optimal value, executable no-SL value, or deployable action value.

## Configured Search Decision Domain

This section is the material semantic update relative to the original T101 contract.

For every restored public state and every particle, retain the **full ordered public legal-action surface** for legality and audit. Every public occurrence must still receive a strict T110/T111 v2 classification.

A public occurrence is one of:

1. searched direct;
2. searched mechanical duplicate mapped to an accepted searched native source edge;
3. configuration-excluded under the accepted T110 rule.

Under this task's frozen `include_potions=false` configuration, valid potion-use or potion-discard public actions may be configuration-excluded. Such occurrences:

- remain present in the ordered public legal surface;
- remain visible in legality/audit evidence;
- must retain the accepted exclusion reason and null Search-edge/evaluation fields with visits zero as required by T110;
- have **no numeric Search proxy**;
- are **not** members of a searched decision class;
- are excluded from `M_N`, ranking, best-set, rank-agreement, opportunity-gap, and convergence calculations;
- must never be imputed as zero or inherit another action's value.

The **configured Search decision domain** is only the searched occurrences/classes.

For searched occurrences:

- every actual Search root edge must be covered;
- every searched occurrence must map to a concrete accepted source edge/equivalence class;
- required visits and values must satisfy the strict current T110/T111 validator;
- duplicate public occurrences sharing one accepted searched source edge count as one decision class for numeric aggregation and ranking;
- duplicate occurrences remain separately retained for public audit and must not receive extra statistical weight.

The searched/excluded occurrence classification and the searched decision-class partition must be identical across all particles used for one state/replicate. Any drift fails closed. T113 must not invent a reconciliation rule.

No Python reimplementation of native mechanical equivalence is permitted.

### Decision stability

- best searched decision-class set;
