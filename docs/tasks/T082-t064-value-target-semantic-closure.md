## Objective

Close the value-target semantic question left unresolved by T080 using the
accepted, non-smoke-scale T064 training lineage and already-retained historical
source trajectories.

T080 established the static semantic-risk surface but could not classify it:
its frozen T043 checkpoint had only four trainer rows, and all four had
`behavior_action` unavailable. T081 then showed that those four-row checkpoints
were diagnostic artifacts and added the scientific artifact eligibility gate.

T064 provides a better evidence source without requiring new model training:
its accepted execution audited 22,343 source records, selected and fresh-restored
460 sources with zero selected duplicates/holdout overlap, generated 460 Oracle
teacher rows and 460 trainer rows, and trained four formal checkpoints. However,
the current Oracle teacher collector intentionally writes
`behavior_action=None`, so simply rerunning the T080 parser on the T064 trainer
would remain unresolved.

T082 fills only that missing behavior-action provenance. It does not generate a
new teacher, train a model, change Search v2, or alter features.

## Scientific Observation Enabling This Task

`BattleStartCheckpointRecord.action_trace` is a chronological,
occurrence-disambiguated history of actual actions taken before the captured
battle start. Source collection captures a battle-start record in
`before_decision`, then appends each actual selected action to the run-level
trace in `after_transition`. A later battle-start record in the same source run
therefore freezes a longer trace.

For a source record `r_i` and the exact next battle-start record `r_{i+1}` from
the same retained source run, when all of the following hold:

1. same exact source-pool artifact and assistance lineage;
2. same `source_run_id` and `source_seed`;
3. `r_{i+1}.source_battle_index == r_i.source_battle_index + 1`;
4. `r_i.action_trace` is a strict element-for-element prefix of
   `r_{i+1}.action_trace` using the repository occurrence-safe action identity;
5. at least one action was appended;

then the first appended action

```text
r_{i+1}.action_trace[len(r_i.action_trace)]
```

is the historical first behavior action actually taken from `r_i`'s battle
start. This is trajectory recovery from retained evidence, not controller
re-execution and not a counterfactual estimate.

If there is no exact next battle-start record (for example the current battle
is the last captured battle in a run), the behavior action remains unavailable.
T082 must not rebuild or approximate the source controller to fill that gap.

## Behavior-Recovery Validity Rules

Behavior recovery is valid only from retained chronological trajectory
identity. In particular:

- do not infer the action from action kind alone;
- do not compare raw legal-action indices across independently reconstructed
  lists;
- do not use model logits, teacher root statistics, filenames, or controller
  names as a substitute for the historical action;
- do not re-run the source controller and call the result historical behavior;
- do not use a later non-adjacent battle record if the immediate
  `source_battle_index + 1` record is missing;
- require strict prefix equality of every prior occurrence-safe action identity;
- any prefix violation is an integrity problem for that attempted comparison,
  not evidence of policy divergence.

Rows without a valid successor remain in all denominators describing total
training rows but are excluded from the auditable teacher-vs-behavior
comparison denominator.

## Value-Target Semantic Audit

Reuse the accepted T080 semantic definitions rather than inventing a new value
meaning:

- policy target: Oracle teacher action/soft-visit target at the T064 restored
  source state;
- behavior action: recovered historical first action from the source trajectory;
- value target: realized source battle outcome (`battle_survived`) carried by
  the T043/T064 trainer contract;
- Search v2 consumer: checkpoint `battle_survival_probability` used as learned
  leaf value at the existing hypothetical-leaf boundary.

The audit must quantify:

- total rows = 460;
- behavior-recoverable and unavailable counts;
- teacher-vs-behavior equal/different counts and divergence rate over auditable
  rows;
- divergence stratified by Act, room type, assistance component, and source
  battle-controller provenance where available;
- survived/lost/unavailable value-label counts overall and among divergent rows;
- divergent rows that simultaneously have an available source outcome;
- exact producer/consumer semantic call-chain facts already established by
  T080, checked against current `main` rather than copied blindly.

No outcome-dependent row selection is allowed. All 460 frozen rows are audited.

## Precommitted Classification

T082 ends in exactly one of the following.

### `VALUE_TARGET_SEMANTIC_MISMATCH_CONFIRMED`

Require all of:

1. all frozen artifact identities and the 460-row selected/teacher/trainer
   linkage pass integrity and eligibility checks;
2. the trainer value target is still the realized source/behavior battle
   outcome;
3. Search v2 still consumes the learned survival head as value at hypothetical
   tree leaves;
4. the policy target is generated by the T064 Oracle teacher contract rather
   than by the source behavior continuation contract;
5. no retained contract establishes the source outcome as the defined value of
   the Search-v2 continuation policy;
6. at least one row has a trajectory-recovered, occurrence-safe behavior action
   different from the Oracle teacher top action;
7. at least one such divergent row has an available source battle outcome/value
   target.

Interpretation: the active T043/T064 training contract operationally combines
an improved-policy target with a value label generated under a different
behavior continuation. This confirms a target-semantic mismatch; it does not
show that value functions themselves are unsuitable.

### `VALUE_TARGET_SEMANTICS_ALIGNED`

Require positive provenance proving that the source-outcome target estimates the
same continuation-policy value that Search v2 requests, plus no contradictory
auditable row. Mere zero observed first-action divergence is insufficient.

Interpretation: value-target repair moves down the priority list and the next
model-side question may proceed to feature/encoding quality.

### `VALUE_TARGET_SEMANTICS_UNRESOLVED`

Use when artifact integrity is valid but retained trajectories do not provide an
auditable divergent row and no positive alignment contract exists, or when
behavior recovery is too sparse to establish either relationship. Missing raw
artifacts, hash mismatch, malformed source ordering, or other integrity failure
is execution `INCOMPLETE`, not a scientific unresolved result.

No classification threshold may be changed after inspecting divergence results.

## Decision Rule After Classification

- `VALUE_TARGET_SEMANTIC_MISMATCH_CONFIRMED`: Planner may publish one bounded
  value-target repair experiment. That successor must change target semantics
  only as far as possible and freeze features/model/search semantics.
- `VALUE_TARGET_SEMANTICS_ALIGNED`: do not create value-target variants; move to
  the feature/encoding semantics audit.
- `VALUE_TARGET_SEMANTICS_UNRESOLVED`: do not automatically retrain. Planner
  compares the cost of a true continuation-value counterfactual experiment with
  the feature/encoding audit.

In every case, update research ledger #85 before publishing a successor.
